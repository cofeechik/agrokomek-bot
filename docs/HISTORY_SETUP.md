# Подключение истории наблюдений

Код готов, но история прежних снимков включается только после подключения постоянной базы. Пока переменные Supabase не заданы, доступно прежнее ручное сравнение двух фото. Локальная SQLite на бесплатном Render не подходит для обещания сохранить историю на неделю.

1. Откройте https://supabase.com/dashboard и создайте проект `AgroKomek` в организации с планом Free. Платный план для этого прототипа не требуется; условия и ограничения смотрите на https://supabase.com/pricing.
2. Дождитесь создания проекта. Откройте SQL Editor, создайте новый запрос и вставьте содержимое `supabase/journal.sql` из этого репозитория. Нажмите Run. Таблица `agro_observations` должна появиться в Table Editor.
3. Скопируйте Project URL (`https://…supabase.co`) и серверный Secret API key (`sb_secret_…`) из настроек API/Connect. Publishable/anon key для бота не подходит. Ключ остаётся только в настройках сервера, его не нужно присылать в чат или коммитить.
4. Render → сервис `agrokomek-bot` → Environment → добавьте:
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_SECRET_KEY` — Secret API key.
5. Сохраните изменения с новым деплоем. После статуса Live отправьте боту новое фото и дождитесь анализа. Нажмите «Наблюдение»: должна появиться запись с датой, культурой и подписью. Выберите её, убедитесь, что показан нужный снимок, и отправьте один новый снимок.
6. Нажмите «Сводка»: появятся количество осмотров, культуры и результаты сравнений. После очередного деплоя запись должна оставаться доступна.

Снимки, отправленные до включения истории, автоматически восстановить нельзя: старый бот не сохранял их идентификаторы. Их можно один раз отправить заново. Указывайте реальную дату съёмки в подписи: дата в списке — время отправки боту.

В базе нет файлов изображений: хранятся Telegram file_id, ID чата, дата, подпись, культура, результат и связь с предыдущим осмотром. Во время сравнения бот повторно получает старый снимок через Telegram. Записи сохраняются до /delete; команда удаляет историю текущего пользователя из базы, не сообщения в Telegram. Доступ между чатами разделён на сервере. Таблица закрыта для anon/authenticated через RLS и права доступа.

Если база недоступна, первичный анализ продолжит работать и сообщит о неудачном сохранении. Сравнение по старой записи потребует восстановления базы. Сводка ограничена 100 последними записями и явно сообщает об этом при превышении.

История сравнивает отдельные снимки. Количество снимков с ухудшением не означает количество заболевших полей, а отметка «сегодня» относится к рекомендации при осмотре в тот день. Статистика квалификации работников в эти вычисления не входит.

Документация: https://supabase.com/docs/guides/getting-started/api-keys и https://supabase.com/docs/guides/database/postgres/row-level-security.
