# Карта источников и решение по использованию

Организаторы перечислили ресурсы для трёх разных треков. AgroKomek подаётся в трек 3, компьютерное зрение в агрономии, задача 3.1: распознавание болезней, вредителей и сорняков по фотографии и выдача рекомендаций. Поэтому в MVP используются только источники, которые проверяют визуальный анализ растений. Ресурсы треков 1 и 2 не превращаются в лишние функции до дедлайна.

## Что уже используется

| Источник | Что даёт | Как используем | Что указываем в сдаче |
| --- | --- | --- | --- |
| PlantVillage | Контролируемые изображения здоровых и поражённых листьев; в наборе есть Potato healthy, Early blight и Late blight | Небольшой независимый smoke-бенчмарк: 3 фото на класс, фиксированный commit, SHA-256 и отдельный test-only manifest | Ссылка, авторы, CC BY-SA 3.0 по карточке набора, размер выборки и ограничения |
| PlantDoc | 2 598 изображений из 13 видов растений и до 17 классов; фотографии ближе к реальным сценам, чем лабораторные листы | Следующий обязательный шаг после MVP: добавить отдельный внешний тест по картофелю, не смешивать с PlantVillage и не менять промпт по результатам | Ссылка, paper, CC BY 4.0, отдельные метрики по источнику |
| Собственные фотографии | Проверяют удобство сценария с телефона и работу отказа на некачественном фото | Перед записью демо взять 3–5 своих снимков без лиц, документов и чужих персональных данных; описать, кто разметил и как | «Собственные тестовые снимки», дата, культура, экспертность разметки; не называть их золотой разметкой без агронома |

PlantVillage и PlantDoc нельзя превращать в обучающий набор для заявления «мы обучили свою нейросеть»: AgroKomek не обучает свою модель, а вызывает Gemini API. Наборы нужны для проверки, демонстрации источников данных и воспроизводимости. Не загружаем датасеты в репозиторий.

## Как использовать PlantDoc

1. Скачать исходный репозиторий из ссылки организаторов.
2. Проверить `LICENSE.txt` и сохранить ссылку на paper.
3. Найти категории картофеля и составить manifest только из файлов `test`.
4. Зафиксировать commit, URL, лицензию и SHA-256 каждого файла.
5. Не использовать эти изображения для изменения промпта или ручной подстройки результата.
6. Запустить тот же `scripts/evaluate.js` отдельным manifest-файлом.
7. В отчёте разделить результаты: PlantVillage — контролируемые снимки, PlantDoc — более сложные снимки из открытого окружения.

Если в PlantDoc не окажется достаточного числа подходящих снимков картофеля, не подменять выборку другими культурами. Честно записать, что второй внешний тест не завершён, и использовать собственные фото только как качественную демонстрацию.

## Что дают ресурсы трека 1 и почему мы пока их не подключаем

| Источник | Практическое применение | Решение для AgroKomek |
| --- | --- | --- |
| Sentinel-2 / Copernicus Browser / Copernicus Data Space | Снимки поля, NDVI/NDMI, динамика растительности, границы и риск-зоны | Не подключать к Telegram MVP: нужна геолокация поля, облачная фильтрация, обработка растров и отдельный сценарий GIS |
| Sentinel Hub / EO Browser | Упрощают поиск, визуализацию и API-доступ к Sentinel-2 | Полезны для будущей версии «карта стресса поля»; это уже отдельное решение трека 1 |
| Landsat 8/9 / EarthExplorer / Landsat Look | Более длинный исторический ряд спутниковых наблюдений | Резерв для анализа истории поля; не нужен для диагноза по листу |
| OpenStreetMap | Дороги, населённые пункты, границы и базовый контекст | Можно добавить карту хозяйств после появления реальных координат; сейчас координаты пользователя не собираем |
| QGIS | Подготовка и проверка слоёв, ручная работа с полигонами и растрами | Инструмент аналитика, не зависимость Telegram-бота |
| Natural Earth | Общие картографические границы | Не даёт нужной точности для конкретного поля; в MVP не нужен |
| OpenTopography | DEM и высота рельефа | Нужен для GIS- и агрорисков, не для фотографии листа |
| EarthMap | Интерфейс анализа спутниковых и геопространственных данных | Использовать как ручной исследовательский инструмент при будущей проверке поля, не как обязательный API |

Copernicus Data Space действительно предоставляет Sentinel-2 L1C/L2A и API для поиска/обработки данных; Sentinel Hub даёт Processing и Catalog API. Это подтверждает реалистичность отдельного GIS-прототипа, но не делает эти сервисы нужными текущему боту. Источник: [Copernicus Sentinel-2](https://dataspace.copernicus.eu/data-collections/copernicus-sentinel-missions/sentinel-2), [Copernicus APIs](https://documentation.dataspace.copernicus.eu/APIs.html).

## Что дают ресурсы трека 2 и почему мы пока их не подключаем

| Источник | Практическое применение | Решение для AgroKomek |
| --- | --- | --- |
| NASA POWER | Бесплатные глобальные метеоданные для температуры, осадков, влажности, радиации и агроклиматологии | Можно построить риск засухи/жары по координатам, но это задача трека 2 и требует периода, культуры, стадии и точки поля |
| ERA5 / ERA5-Land | Ряды реанализа для климата и почвенной температуры/влаги | Нужны для исторической модели рисков, не для CV-диагноза |
| Open-Meteo Historical API | Удобный HTTP-доступ к ERA5/ERA5-Land и исторической погоде; есть данные с 1940/1950 годов в зависимости от набора | Единственный разумный кандидат для будущей кнопки «погодный контекст», но не добавлять без координат и валидации |
| FAOSTAT | Статистика урожайности и производства по странам/культурам | Только фон для слайдов и обоснования проблемы; национальные/региональные выводы брать из источников РК |
| Бюро нацстатистики РК / data.gov.kz / МСХ РК | Региональные культуры, площади, урожайность, официальные документы | Нужны для расчёта экономического эффекта; нельзя приписывать Акмолинской области цифры без конкретной таблицы и года |
| Казгидромет | Региональные метеонаблюдения и предупреждения | Источник для будущей локальной агрорисковой модели и проверки погодного контекста |
| GEOGLAM Crop Monitor | Международный мониторинг состояния посевов и рисков | Контекст для будущего мониторинга, не входной сигнал текущей модели |

Исторический Open-Meteo строится на реанализах ERA5/ERA5-Land и возвращает погодные переменные по координатам и датам. NASA POWER даёт официально документированный API и глобальные агроклиматические данные. Это подходящие источники для отдельного трека 2, но добавление их в текущий бот создаст обещание прогнозировать риск без обученной и проверенной модели. Источники: [Open-Meteo Historical API](https://open-meteo.com/en/docs/historical-weather-api), [NASA POWER API](https://power.larc.nasa.gov/api/pages/).

## Отдельные визуальные сервисы

| Источник | Что умеет | Решение |
| --- | --- | --- |
| Roboflow Universe | Открытые наборы и модели для детекции/сегментации; лицензии нужно проверять у каждого проекта | Использовать только если найдётся подходящий набор с разрешённой лицензией и конкретной задачей; не скачивать случайный датасет |
| Agriculture-Vision | 21 061 аэрофотоснимок полей RGB+NIR с масками сорняков, воды, пропусков и других паттернов | Это сильный материал для дронов и трека 1/задач детекции поля, но не для фото листа картофеля; не подключать |
| PlantNet API | Идентификация вида растения, до 5 фото одного растения и score 0–1; нужен отдельный ключ и действуют условия API | Не нужен для болезни листа. Можно добавить позже как второй этап «проверить культуру», но не смешивать его score с вероятностью болезни |
| iNaturalist | Набор наблюдений живых организмов и изображения с лицензиями на уровне наблюдения | Для общей идентификации видов; не считать источником разметки болезней без проверки лицензии и класса |

Agriculture-Vision ограничен условиями доступа и использования, включая запрет коммерческого продукта, срок использования и требование удалить копии после периода. Поэтому его не берём в этот проект. PlantNet возвращает вероятности вида, а не подтверждение болезни; его результат нельзя показывать фермеру как диагноз.

## Что делаем до сдачи

1. Оставляем основной сценарий: фото листа картофеля → предварительная гипотеза → признаки → безопасные шаги проверки.
2. Добавляем отдельную PlantDoc-проверку, если категории и лицензия подходят без сомнений.
3. Делаем 3–5 собственных фото для демонстрации работы с телефона.
4. В `docs/VALIDATION.md` показываем размеры выборок, Accuracy, macro-F1, ошибки и время.
5. В презентации показываем один источник для контролируемой проверки, один источник для более сложных фото и честные ограничения.
6. Не добавляем карту, урожайность, погоду, Sentinel API, PlantNet и новые ключи до завершения этих пунктов.

## Возможное развитие после хакатона

Единый продукт можно расширить двумя отдельными модулями:

`Фото растения → CV-модуль AgroKomek`  
`Координаты поля → Sentinel-2/NDVI-модуль`  
`Координаты + культура + дата → погодный модуль NASA POWER/Open-Meteo`

Их результаты можно будет объединить в агрономический риск, но для этого понадобятся реальные поля, согласие на координаты, полевые метки и отдельная валидация каждого сигнала.
