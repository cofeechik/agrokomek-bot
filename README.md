# 🌿 AgroKomek

**Фото растения → предварительная оценка → следующие действия.**

Telegram-бот для AgriTech AI Hackathon, Aqmola Hub. Трек 3, задача 3.1: распознавание проблем растения по фото с телефона. Основной сценарий MVP — листья картофеля. Пшеница, томат и другие растения доступны в экспериментальном режиме, их качество не подтверждено.

Бот: https://t.me/AgroKomek_bot. Доступность зависит от запущенного экземпляра приложения.

## Для кого и какую проблему решаем

Фермеру нужно понять, что проверить при появлении пятен на листьях, какие дополнительные фотографии сделать и когда обратиться к агроному. AgroKomek сокращает путь от фотографии к первичной оценке. Он не подтверждает возбудителя и не назначает химическую обработку по одному снимку.

## Что работает

- Русский и казахский интерфейс, выбор языка и культуры.
- Приём фото и JPEG/PNG/WebP-документов до 8 МБ. Проверка содержимого, разрешения, ограничение 24 мегапикселя, уменьшение до 1280 px, удаление метаданных.
- Анализ через Gemini 3.5 Flash с проверкой структурированного ответа.
- Видимые признаки, гипотеза, альтернативные причины, шаги осмотра, уточняющий вопрос.
- Отказ от диагноза для нерелевантного, нечёткого или неоднозначного изображения.
- Последний текст результата, удаление персональных настроек.
- Ограничения расхода: 5 попыток на пользователя и 50 на экземпляр в сутки UTC; максимум 2 параллельных анализа.
- Защита webhook секретом, ограничение размера запроса, обработка повторных обновлений.

Не показываем проценты уверенности: самооценка языковой модели не является измеренной вероятностью диагноза. Срочность — предложение о сроке осмотра, не прогноз потерь.

## Локальный запуск

Требуется Node.js 24.x. Python, FastAPI и Streamlit не нужны: сервер и бот работают одним процессом Node.js.

```sh
npm ci
```

Скопируйте `.env.example` в `.env`, внесите два ключа и оставьте `BOT_MODE=polling`. Затем:

```sh
npm run check
npm test
npm start
```

Откройте бота, отправьте `/start`, выберите культуру и пришлите фото. Симптомы напишите в подписи к фото; отдельные текстовые ответы пока не образуют историю диалога с ИИ. Компьютер должен оставаться включённым. Остановка — Ctrl+C. Нельзя одновременно запускать два polling-процесса с одним токеном.

В `.env` и настройках хостинга:

| Переменная | Назначение |
| --- | --- |
| TELEGRAM_BOT_TOKEN | Токен BotFather |
| GEMINI_API_KEY | Ключ Google AI Studio |
| GEMINI_MODEL | `gemini-3.5-flash`, проверяется через `npm run check` |
| BOT_MODE | `polling` локально, `webhook` на Render |
| WEBHOOK_URL | HTTPS-адрес сервиса; на Render берётся RENDER_EXTERNAL_URL |
| WEBHOOK_SECRET | Секрет из 16–64 букв, цифр, `_` или `-`; например `AgroKomekWebhook2026_x7` |
| PORT | По умолчанию 3000; Render задаёт свой порт |
| USER_DAILY_LIMIT / DAILY_ANALYSIS_LIMIT | Лимиты попыток, 5 / 50 по умолчанию |

`.env`, база и фотографии исключены из Git. Если токен опубликован, замените его у провайдера и обновите локальный файл/настройки хостинга.

## Render

1. Остановите локальный экземпляр.
2. В Render выберите **New → Blueprint**, подключите репозиторий и его `render.yaml`.
3. Введите TELEGRAM_BOT_TOKEN и GEMINI_API_KEY. Проверьте бесплатный план перед созданием.
4. В настройках сервиса добавьте `WEBHOOK_SECRET` вручную: только латинские буквы, цифры, `_` или `-`, длина 16–64 символа. После сборки дождитесь успешного `/healthz`. Webhook будет зарегистрирован автоматически.
5. Проверьте `/start`, оба языка, фото растения и фото предмета.

При ручном создании Web Service: Build `npm ci`, Start `npm start`, Health check `/healthz`, BOT_MODE=`webhook`, WEBHOOK_SECRET — случайный секрет минимум 16 символов. WEBHOOK_URL можно не задавать на Render.

**Ограничения бесплатного Render:** сервис засыпает после 15 минут без входящих запросов; холодный запуск задержит даже первое сообщение «Фото получено». Локальная SQLite-база на бесплатном непостоянном диске может потеряться после перезапуска/пересоздания: история, дедупликация и лимиты тогда сбросятся. Для постоянной публичной эксплуатации нужны постоянное хранилище и внешние лимиты. Лимиты приложения не являются гарантией отсутствия расходов у Google. Квоты зависят от проекта Google и модели.

Webhook принимает задания в память. Аварийное завершение после HTTP 200 может потерять незавершённый анализ; тогда пользователь повторно отправляет фото. Для MVP используется один экземпляр. Долговечная очередь — следующий этап.

## Данные, модель, проверки

Первичная проверка: **8 из 9** реальных лабораторных фото, macro-F1 0,886; медиана API и обработки 9,24 с. Это маленькая техническая выборка, не доказанная точность продукта. Подробности и ограничения: [docs/VALIDATION.md](docs/VALIDATION.md).

Используется готовая мультимодальная модель Gemini через облачный API. Собственная нейросеть не обучалась. Промпт и схема ответа находятся в `src/analysis.js`.

Скрипт `scripts/fetch-samples.js` выбирает 9 реальных изображений PlantVillage: по 3 для картофеля без видимых признаков болезни, альтернариоза и фитофтороза. Выбор детерминирован, файлы фиксируются по commit и SHA-256. Это **маленькая техническая проверка**, не подтверждение точности на полях Акмолинской области.

Источник: [PlantVillage](https://github.com/spMohanty/PlantVillage-Dataset), Mohanty, Hughes & Salathé, 2016, DOI: 10.3389/fpls.2016.01419. Лицензия по [карточке авторского датасета](https://huggingface.co/datasets/mohanty/PlantVillage): CC BY-SA 3.0. Фотографии не включены в репозиторий; скачиваются отдельно с сохранением источников. При перераспространении соблюдайте условия лицензии.

```sh
node scripts/fetch-samples.js
npm run eval -- eval/private/manifest.json
```

Результат: `eval/results.local.json`. Скрипт считает Accuracy, macro-F1, медиану, p95 и долю запросов до 5 секунд. Ошибки API и отказ от вывода считаются неправильным ответом. Неполный прогон явно помечается. Для серьёзной оценки нужен заранее отделённый набор реальных полевых фото с экспертными метками. Состав обучающих данных Gemini неизвестен: отсутствие пересечения с PlantVillage гарантировать нельзя. Наши проверочные фото не используются для обучения или подбора промпта после просмотра результатов.

`npm test` проверяет программную логику на моках и синтетических технических файлах; это не оценка агрономического качества. `scripts/smoke.js` отправляет синтетическое однотонное изображение для проверки отказа от распознавания. Оно не включается в метрики реальных данных.

В ТЗ указан отклик до 5 секунд. Это требование нельзя считать выполненным без измерений полного пути Telegram → бот → Gemini → Telegram. Встроенный замер включает скачивание фото и анализ, но исключает ожидание до запуска обработчика; eval измеряет обработку и API. Холодный старт Render увеличивает задержку.

## Приватность

Фотография обрабатывается в памяти и отправляется Google Gemini; бот не сохраняет файл. Хранятся Telegram chat ID, язык, культура, последний текст результата до 7 дней. Счётчики и ID обновлений — до 48 часов. `/delete` удаляет настройки и результат; антиспам-счётчики сохраняются до истечения срока. Telegram и Google имеют собственные условия обработки данных. Не отправляйте личные документы и лица.

## Архитектура

Telegram → один процесс Node.js → подготовка изображения → Gemini → проверка JSON → сообщение пользователю. SQLite хранит настройки и счётчики. HTTP-сервер используется для webhook и проверки готовности; отдельный сайт пользователю не нужен.

Официальная документация: [Telegram Bot API](https://core.telegram.org/bots/api), [Gemini image understanding](https://ai.google.dev/gemini-api/docs/image-understanding), [Render free services](https://render.com/docs/free).
